# Bug Report — Equity Analytics Pipeline

Generated by AI code review across 4 batches. Issues triaged and prioritized below.

---

## Fixed (branch: fix/critical-issues)

### F1 — SQL injection in load.py `get_max_date` / `get_min_date`
**File:** `ingestion/load.py`
**Fix:** Added `_validate_table_name()` whitelist with `frozenset` of allowed table names. Applied to both functions before f-string interpolation.
**Why critical:** Table name came from caller-supplied string with no validation. Any caller passing an attacker-controlled value could inject arbitrary SQL.

### F2 — `CAST` failures on yfinance string sentinels in `stg_valuation_metrics.sql`
**File:** `dbt_project/models/staging/stg_valuation_metrics.sql`
**Fix:** Replaced all `cast()` with `try_cast()` for numeric columns (float and bigint). `cast(extracted_at as timestamp_ntz)` left as CAST — timestamp column is pipeline-controlled.
**Why critical:** yfinance returns strings like `'N/A'`, `'Infinity'` for missing fields. Plain `CAST` throws a hard error and fails the entire dbt run.

### F3 — Value sentinel cap too high in `extract_fundamentals.py`
**File:** `ingestion/extract_fundamentals.py` line 220
**Fix:** Changed `abs(value) > 1e18` → `abs(value) > 1e15`.
**Why:** 1e18 = $1 quintillion. No financial metric reaches that. Legitimate ceiling is ~$1 quadrillion (1e15). yfinance occasionally returns large sentinel floats (e.g., `1e308`) for missing data; the old threshold let those through, corrupting downstream aggregations.

### F4 — Circuit breaker missing in `extract_all_fred_series`
**File:** `ingestion/extract_fred.py`
**Fix:** `extract_fred_series` now returns `None` (not empty DataFrame) for network failures (Timeout, ConnectionError). `extract_all_fred_series` counts consecutive `None` returns and aborts after `CIRCUIT_BREAKER_THRESHOLD = 5`.
**Why critical:** Without a circuit breaker, a FRED API outage causes all 175 series to be attempted, wasting minutes, burning API quota, and potentially triggering rate-limit bans.

### F5 — `re.match` vs `re.fullmatch` for ticker validation in `event_study.py`
**File:** `app/components/event_study.py` line 34
**Fix:** Changed `re.match(r'^[A-Z0-9\-]{1,10}$', ticker)` → `re.fullmatch(r'[A-Z0-9\-]{1,10}', ticker)`.
**Why:** `re.match` anchors at the start but not the end (the `$` in the pattern partially compensates, but `re.fullmatch` is unambiguous). The ticker is used directly in a SQL f-string; the regex whitelist is the only injection guard.

### F6 — Hardcoded Airflow credentials in `docker-compose.yml` (D1)
**File:** `docker-compose.yml`
**Fix:** All credentials parameterized via environment variables:
- `POSTGRES_USER/PASSWORD` → `${AIRFLOW_DB_USER}` / `${AIRFLOW_DB_PASSWORD}`
- `AIRFLOW__DATABASE__SQL_ALCHEMY_CONN` → uses `${AIRFLOW_DB_USER}:${AIRFLOW_DB_PASSWORD}`
- `AIRFLOW__WEBSERVER__SECRET_KEY` → `${AIRFLOW_SECRET_KEY}`
- Admin password → `${AIRFLOW_ADMIN_PASSWORD}`
- `.env.example` updated with all new variables and rotation warning.

**ACTION REQUIRED:** The original `docker-compose.yml` with `airflow:airflow` and `admin:admin` credentials was pushed to a public repo. Rotate the Airflow metadata DB password and admin password immediately:
```bash
# 1. Set strong credentials in .env
# 2. Tear down and re-init the stack:
docker-compose down -v   # drops the DB volume
docker-compose up airflow-init
docker-compose up -d
```

### F7 — Write operations not blocked in chat SQL interface (D5)
**File:** `app/db/snowflake.py`
**Fix:** Added `_assert_read_only(sql)` called from `_run_query` before every execution. Strips SQL comments, then:
1. Asserts first keyword is `SELECT` or `WITH` (rejects DML entry points)
2. Scans for write keywords: `INSERT`, `UPDATE`, `DELETE`, `DROP`, `CREATE`, `ALTER`, `TRUNCATE`, `MERGE`, `REPLACE`, `GRANT`, `REVOKE`, `EXECUTE`, `CALL`
Raises `ValueError` on violation — surfaced as an error in the Streamlit UI.

### F8 — No canary test for yfinance field renames in `int_fundamentals_pivoted.sql` (D6)
**File:** `dbt_project/tests/assert_fundamentals_revenue_not_null.sql` (new)
**Fix:** Singular dbt test that asserts AAPL annual rows have non-null `total_revenue`. If yfinance renames `'Total Revenue'`, this test fails on the next dbt run instead of silently producing NULLs.

### F9 — Adaptive backoff missing in FRED extraction (was: "fixed 0.5s delay")
**File:** `ingestion/extract_fred.py`
**Fix:**
- Added `_RateLimitError` exception raised on HTTP 429
- `extract_all_fred_series` has a retry loop per series: on 429, doubles the delay (capped at 30s) and retries
- On each successful fetch, delay reduces by 10% (toward `_DELAY_BASE = 0.5s`)
- `time.sleep(delay)` added between every series request

### F10 — Adaptive backoff missing in yfinance extraction (was: "fixed 2s delay")
**File:** `ingestion/extract_fundamentals.py`
**Fix:** Applied to both `extract_financial_statements` and `extract_valuation_metrics`:
- On successful ticker: delay reduces by 10% toward floor of `delay_seconds * 0.5`
- On failed ticker exception: delay doubles (capped at 30s)
- `time.sleep(delay)` between tickers uses the adaptive value

### F11 — Missing FRED API key validation in `dag_fred_catalog.py` (D7)
**File:** `airflow/dags/dag_fred_catalog.py` (on branch: `fred-series-expansion`)
**Fix:** Changed `os.environ["FRED_API_KEY"]` → `os.environ.get("FRED_API_KEY")` with explicit `ValueError` if missing.
```python
api_key = os.environ.get("FRED_API_KEY")
if not api_key:
    raise ValueError("FRED_API_KEY environment variable is required but not set")
```
Applied as a separate commit on `fred-series-expansion`.

## Deferred Issues

### D2 — Private key file on filesystem (not in secrets manager)
**File:** `docker-compose.yml`, `app/db/snowflake.py`
**Risk:** `snowflake_private_key.pem` lives on disk and is mounted into the container.

| | Detail |
|---|---|
| **Pros of leaving** | Key file is gitignored. Local-only deployment means no remote attacker can reach the filesystem. RSA key auth is still far better than password auth. |
| **Cons of leaving** | No key rotation mechanism. If the machine is compromised, the key grants full Snowflake access with no expiry. For cloud deployment, must migrate to a secrets manager before launch. |
| **Fix when:** Before Streamlit Community Cloud deployment — store key in Streamlit secrets or cloud secrets manager. |

---

### D3 — Shell command injection risk in `db_health.py` `_docker_status()`
**Lines:** 165–173
**Risk:** `subprocess` call without explicit `shell=False` and without sanitizing arguments.

| | Detail |
|---|---|
| **Pros of leaving** | `_docker_status()` only runs in admin/health-check context. Arguments are hardcoded Docker CLI commands, not user-supplied input. |
| **Cons of leaving** | If the function evolves to accept configurable container names, the injection surface opens immediately. |
| **Fix when:** Next time `db_health.py` is refactored. Add `shell=False` explicitly. |

---

### D4 — Hardcoded schema `EQUITY_ANALYTICS.MARTS` in `snowflake.py`
**Lines:** Multiple queries in `app/db/snowflake.py`
**Risk:** No environment separation — CI/dev queries hit the same prod schema as prod.

| | Detail |
|---|---|
| **Pros of leaving** | Single environment (local dev + one Snowflake account) means hardcoding works today. |
| **Cons of leaving** | Cannot point the app at a staging schema. Any schema rename requires grep-and-replace across files. For Community Cloud, want a read-only replica option. |
| **Fix when:** When adding a staging environment or deploying to Community Cloud. Use `SNOWFLAKE_SCHEMA` env var. |
